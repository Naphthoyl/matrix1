# Matrix + List

Учебный проект на C++17: **двусвязный список квадратных матриц** с двумя курсорами. Матрицы читаются из текстового файла, а все пользовательские данные перед разбором проверяются регулярными выражениями.

Что внутри:

- `Matrix<T>` - квадратная матрица со сложением, умножением и вычислением следа;
- `List<T>` - двусвязный список матриц с курсорами `before` и `after`, между которыми можно вставлять и удалять элементы;
- `Node<T>` - узел списка;
- проверка входных данных через `std::regex`;
- параметры командной строки и конфиг-файл через `Boost.Program_options`;
- юнит-тесты на `doctest`;
- сборка через CMake.

Классы шаблонные, явно инстанцируются для `int` и `double`. Память управляется умными указателями (`std::unique_ptr`), ручных `new` и `delete` в проекте нет.

## Сборка

Нужны компилятор с поддержкой C++17 и CMake 3.24 или новее.

### Через CMake (рекомендуется)

```bash
cmake -S . -B build
cmake --build build
```

Boost (компонент `program_options`) CMake скачает сам через `FetchContent`, поэтому для первой сборки нужен интернет. В `build/` появятся:

| Файл | Что это |
| --- | --- |
| `app/app` | основная программа |
| `app/text.txt`, `app/config.cfg` | копии входных файлов, чтобы программа находила их рядом с собой |
| `tests/test` | юнит-тесты |

На MinGW программа линкуется статически (`-static`), так что для запуска не нужны посторонние DLL.

### Через g++

Если Boost уже установлен в системе:

```bash
g++ -std=c++17 -Wall -Iinclude app/main.cpp src/matrix/matrix.cpp src/node/node.cpp src/list/list.cpp \
    -lboost_program_options -o app
```

Флаг `-Iinclude` нужен, чтобы компилятор нашёл заголовки в папке `include/`.

## Запуск

```bash
cd build/app
./app                    # читает файл из config.cfg или text.txt
./app -f my_data.txt     # читает указанный файл
./app --help             # список опций
```

### Опции

| Опция | Описание |
| --- | --- |
| `-f`, `--file` | входной файл с матрицами (по умолчанию `text.txt`) |
| `--help` | показать справку |

Приоритет значений: аргумент командной строки, затем `config.cfg`, затем значение по умолчанию.

Пример `config.cfg`:

```
file=text.txt
```

## Формат входных данных

```
2        <- сколько всего матриц
2        <- размер первой матрицы
1 2
3 4
3        <- размер второй матрицы
1 0 0
0 1 0
0 0 1
```

Сначала идёт количество матриц, затем для каждой матрицы её размер `n` и `n` строк по `n` целых чисел. Числа в строке разделяются одним пробелом.

### Что выведет программа

Для файла выше:

```
vvedite elementi
vvedite elementi
5
3
1  2  
3  4  

1  0  0  
0  1  0  
0  0  1  
 <-before
```

Сначала по одной строке на матрицу (служебное сообщение при вводе), потом след каждой матрицы (`5` = 1 + 4, `3` = 1 + 1 + 1), затем все матрицы списка. Пометка `<-before` показывает, где стоит курсор: после чтения он находится за последней матрицей.

## Проверка данных (regex)

Перед тем как читать матрицы, `main.cpp` проверяет всё, что пришло от пользователя, регулярными выражениями (`std::regex`). Если что-то не так, программа выводит номер строки с ошибкой и завершается.

| Что проверяется | Регулярное выражение | Правило |
| --- | --- | --- |
| Имя файла (`--file`) | `[\w./\\:-]+\.txt` | допустимые символы пути, расширение `.txt` |
| Количество матриц и размер матрицы | `[1-9]\d{0,2}\r?` | целое от 1 до 999 |
| Строка матрицы | `-?\d{1,9}( -?\d{1,9}){n-1}\r?` | ровно `n` целых чисел через пробел, до 9 цифр (чтобы не переполнить `int`) |

`\r?` в конце нужен, чтобы файлы с Windows-переводами строк (`\r\n`) тоже читались.

Пример сообщения об ошибке:

```
error in line 4: bad matrix row
```

### Коды возврата

| Код | Причина |
| --- | --- |
| `0` | всё прошло успешно |
| `-1` | файл не удалось открыть |
| `-2` | в файле некорректное количество матриц |
| `-3` | ошибка в параметрах командной строки или конфиге |
| `-4` | недопустимое имя файла |
| `-5` | данные в файле не прошли проверку |

## Как устроен список

`List` хранит матрицы в цепочке узлов. Между двумя соседними узлами находится «щель» с двумя курсорами: `before` смотрит на элемент слева, `after` на элемент справа.

```
  [A] <-> [B] | [C] <-> [D]
              ^
       before=B    after=C
```

Вставка и удаление происходят именно в этом месте, поэтому они выполняются за O(1).

### Методы `List<T>`

Методы с кодом возврата возвращают `0` при успехе и `-1`, если операция невозможна (например, курсор уже в конце).

| Группа | Методы | Что делают |
| --- | --- | --- |
| Вставка | `ins_before(m)`, `ins_after(m)` | вставить матрицу слева или справа от курсора |
| Удаление | `del_before()`, `del_after()` | удалить элемент слева или справа от курсора |
| Чтение и запись | `get_before(m)`, `get_after(m)`, `set_before(m)`, `set_after(m)` | скопировать значение из элемента или в него |
| Движение | `step_forward()`, `step_backward()`, `go_to_beg()`, `go_to_end()` | сдвинуть курсор на шаг, в начало или в конец |
| Состояние | `at_beg()`, `at_end()`, `is_empty()` | вернуть `1`, если курсор в начале или конце, либо список пуст |
| Операции | `sum(result)`, `mul(result)` | сложить или перемножить матрицы слева и справа от курсора |
| Вывод | `show()`, `sled()` | показать список или вывести след каждой матрицы |

Копирующий конструктор и оператор присваивания делают глубокую копию вместе с положением курсоров.

### Методы `Matrix<T>`

| Метод | Описание |
| --- | --- |
| `Matrix(n)` | матрица `n x n` |
| `input(fin)` | прочитать элементы из файлового потока |
| `show()` | вывести матрицу |
| `operator+`, `operator*` | сложение и умножение (при разных размерах вернётся пустая матрица) |
| `sledMatrix()` | вывести след матрицы (сумму диагонали) |

## Тесты

Тесты написаны на [doctest](https://github.com/doctest/doctest) и покрывают список: вставку, удаление, движение курсоров, `get`/`set`, `sum`/`mul`, копирование и присваивание, работу с `double`.

```bash
cmake --build build --target test
./build/tests/test
```

Или без CMake:

```bash
g++ -std=c++17 -Iinclude -Itests tests/test.cpp src/matrix/matrix.cpp src/node/node.cpp src/list/list.cpp -o test
./test
```
